# 系统约束治理

系统约束只保留一条主线：

```text
MVP -> 顶层能力 -> 下层行为 -> 测试 -> 状态
```

## 模型

- **MVP**：说明调用方提交什么，系统生成什么，并交付什么结果。
- **顶层能力**：共同组成 MVP 的独立产品能力，数量由项目决定。
- **下层行为**：一个顶层能力在一种条件下必须产生的可观察结果，标记为 `normal` 或 `variant`。
- **测试**：验证一条下层行为的测试用例和独立预言机。

顶层能力通常是范围确立、主要产物生成或结果投影。鉴权、协议协商、运行时兼容、验证、分类、判断、评分、抽取、重试、重放、缓存、并发和恢复通常属于下层行为；分类、判断或评分只服务于主要产物时，顶层使用主要产物命名。判断边界时，删除该条后 MVP 不再完整才保留为顶层；只是已有能力在不同条件下的结果则归入下层。

顶层能力按自身产生的业务产物命名，例如“确认材料范围”“生成主要产物”“投影调用方结果”。鉴权、协议和可靠性机制只能修饰这些产物的行为，不能成为顶层名称。

## 识别范围与覆盖复核

顶层能力以调用方可独立获得和验收的交付结果为单位，不以代码目录、类、接口或架构模块数量为上限。一个主要模块可以承载多个独立交付结果，也可以只是其他能力的支撑实现。

先从需求、产品决策、用户工作流、主要界面或视图、公开 API 和导出物列出候选交付结果。删除一项后，调用方不再能取得一个独立结果时，它应成为顶层能力；只是另一结果在异常、权限、兼容、资源或并发条件下的表现时，它应成为下层行为。

完成顶层能力识别后，复核架构资料中的每个主要模块。每个模块必须明确归入以下之一：

- 一个或多个顶层能力，并说明各自交付的独立结果。
- 某项顶层能力的下层行为，并说明它只改变该能力在何种条件下的结果。
- 支撑组件，并说明它不直接向调用方交付独立结果。

再用同一方式复核主要界面或视图、公开 API 和导出物。任何未映射的项目都表示识别未完成，不能只因顶层能力数量看起来合理而结束。

### 默认候选与合并证明

每个主要用户工作流中的主界面或视图、可由调用方直接使用的公开 API 族、可保存或传递的导出物，以及独立对外提供结果的服务，都先建立顶层能力候选。共享同一份记录、同一个架构模块或同一条数据流，不能单独作为合并理由。

候选可以合并为另一项能力的下层行为或支撑组件，但必须同时证明：

1. 调用方不能将它作为独立结果请求或进入。
2. 调用方不能用独立预言机验收它的结果。
3. 它只改变父能力在特定条件下的表现，或只提供父能力不可见的实现支撑。

每次合并都记录候选项、父能力、合并理由和上述证明依据。缺少任一项时保留为顶层候选。完成删除并清理所有可达入口、文档、测试和导出物的能力标记为 `retired`；实现、文档或测试仍互相矛盾的退役工作保持 `candidate` 并列为待确认事项。

## 授权

顶层能力的建立、规则变更和退役只在用户当前任务明确要求时进行。普通实现、重构和修复保持顶层语义不变，只补充或修复不改变父能力语义的下层行为与测试。

## 工作流

1. 阅读需求、架构资料、源码、有效测试和运行事实，写出一句 MVP。
2. 从用户工作流、主要界面或视图、公开 API 族、导出物和对外服务建立顶层能力候选清单。每项候选记录独立请求入口、独立交付结果和独立验收预言机。
3. 只在有完整合并证明时，将候选归入另一项能力的下层行为或支撑组件；否则保留为顶层能力。再识别共同还原 MVP 的顶层能力，每项规则写明业务条件、系统动作和可观察结果，并放入唯一正式架构位置。
4. 对主要模块、界面或视图、公开 API 和导出物完成覆盖复核。一个模块可映射多个顶层能力，但不得以模块数量限制能力数量；每个映射都记录归类和理由。
5. 为每项顶层能力识别至少一个 `normal` 行为和一个 `variant` 行为。每条行为只说明一个条件下的结果。
6. 为每条行为构建或定位一条测试，记录测试文件、定位、预期结果和独立预言机。
7. 将 MVP、顶层规则、依据、下层行为和测试映射登记到项目约束账本，运行对应项目测试。

`active` 顶层能力必须具备意图依据、现状依据、正常行为、变体行为及其测试。只读分析或测试未执行、失败时，相关顶层能力和行为保持 `candidate`。顶层能力被明确取消或替代时标记为 `retired`。

只读分析不写入账本，但仍须完整交付 MVP、候选清单及其独立请求入口和验收预言机、能力合并记录、交付结果与模块/界面/API/导出物覆盖映射、每项能力的正常和变体行为、每项行为的测试与独立预言机，以及未映射项或待确认事项。缺少其中任何一项时，报告识别未完成。

## 交付检查

- 只读顶层能力即可理解 MVP 接收什么、生成什么和交付什么。
- 每条下层行为只归属一个顶层能力，且不重复顶层规则。
- 每条下层行为都有可定位测试和独立预言机。
- 顶层规则、下层行为和测试映射均可追溯到项目材料。
- 每个独立交付结果和每个主要模块、界面或视图、公开 API、导出物都有归类；未映射项保留为待确认事项。
- 每项被合并的候选都有父能力、合并理由及不可独立请求、不可独立验收、仅改变父能力或提供支撑的证明。
- 输出不混入框架、接口、字段、部署或内部调用细节。
